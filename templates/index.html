 Smart Contract Weakness Classification (SWC) Knowledge Base

                
This library details the most dangerous smart contract vulnerability archetypes, their real-world economic impacts, and code patterns comparing vulnerable implementations against secure remediations.

            


            

                
                

                    

                        
CRITICAL · SWC-107

                        
Historic Incident: The DAO ($60M Loss)

                    

                    
Reentrancy Attack

                    
Occurs when an external contract call transfers control back to the caller before state variables are updated, allowing the attacker to recursively drain funds.


                    

                        

                            

                                
                                Insecure Pattern (State updated after call)
                            

                            
// External call BEFORE balance reset
(bool ok, ) = msg.sender.call{value: bal}("");
require(ok);
balances[msg.sender] = 0; // State update happens too late!

                        

                        

                            

                                
                                Secure Remediation (Checks-Effects-Interactions)
                            

                            
// Update state BEFORE external interaction
balances[msg.sender] = 0; // State cleared first
(bool ok, ) = msg.sender.call{value: bal}("");
require(ok, "Transfer failed");

                        

                    

                


                
                

                    

                        
HIGH · SWC-101

                        
Historic Incident: BeautyChain BEC ($1B Impact)

                    

                    
Integer Overflow & Underflow

                    
Occurs when arithmetic operations exceed storage boundaries (e.g., uint256 max + 1 wrapping around to 0), bypassing transfer limits or creating infinite tokens.


                    

                        

                            

                                
                                Insecure Pattern (Raw math in Solidity <0.8)
                            

                            
// Unchecked batch multiplication overflows
uint256 total = cnt * _value; // Wraps to ~0
require(balances[msg.sender] >= total);

                        

                        

                            

                                
                                Secure Remediation (Solidity 0.8+ or SafeMath)
                            

                            
// Built-in arithmetic check auto-reverts on overflow
pragma solidity ^0.8.0;
uint256 total = cnt * _value; // Built-in compiler safety

                        

                    

                


                
                

                    

                        
MEDIUM · SWC-115

                        
Historic Incident: Run Lottery Exploit

                    

                    
Insecure Randomness (Timestamp Dependency)

                    
Using block variables (`block.timestamp`, `block.number`, `blockhash`) as pseudo-random generators allows miners and bots to predict outcomes beforehand.


                    

                        

                            

                                
                                Insecure Pattern (Predictable block variable)
                            

                            
// Miner can manipulate or predict outcome
uint random = uint(keccak256(
    abi.encodePacked(block.timestamp, blockhash(block.number - 1))
)) % 100;

                        

                        

                            

                                
                                Secure Remediation (Chainlink VRF Verifiable Randomness)
                            

                            
// Cryptographic verifiable random oracle
import "@chainlink/contracts/VRFConsumerBase.sol";
requestRandomness(keyHash, fee);

                        

                    

                


                
                

                    

                        
CRITICAL · SWC-112

                        
Historic Incident: Parity Multi-Sig ($30M Loss)

                    

                    
Dangerous Delegatecall

                    
Delegatecall executes target bytecode within the calling contract's storage context. Calling an untrusted address allows malicious code to overwrite owner storage.


                    

                        

                            

                                
                                Insecure Pattern (Arbitrary target delegatecall)
                            

                            
// Attacker can pass target = malicious contract
target.delegatecall(abi.encodeWithSignature("initWallet()"));

                        

                        

                            

                                
                                Secure Remediation (Whitelisted Implementation)
                            

                            
// Whitelist target address or use formal proxies
require(target == trustedLibrary, "Untrusted target");
(bool ok, ) = target.delegatecall(data);

                        

                    

                


                
                

                    

                        
CRITICAL · SWC-105

                        
Historic Incident: Rubixi Ponzi Scheme

                    

                    
Unprotected Function / Broken Access Control

                    
Administrative functions (such as `setOwner`, `withdraw`, `mint`) exposed as public without modifier enforcement allow anyone to take ownership.


                    

                        

                            

                                
                                Insecure Pattern (Missing modifier / constructor typo)
                            

                            
// Misnamed constructor allows public ownership takeover
function DynamicPyramid() public {
    owner = msg.sender; // Anyone can call this anytime!
}

                        

                        

                            

                                
                                Secure Remediation (Keyword constructor + modifier)
                            

                            
// Modern keyword constructor + onlyOwner modifier
constructor() {
    owner = msg.sender;
}
function setOwner(address newOwner) external onlyOwner { ... }

                        

                    

                


                
                

                    

                        
HIGH · SWC-128

                        
Historic Incident: King of the Ether Throne

                    

                    
Denial of Service via Unbounded Loops

                    
Iterating over an unbounded array to push ether payments will cause the transaction to exceed block gas limits, permanently locking contract state.


                    

                        

                            

                                
                                Insecure Pattern (Push payment in unbounded loop)
                            

                            
// Fails if 1 address reverts or gas limit exceeded
for (uint i = 0; i < payees.length; i++) {
    require(payees[i].transfer(amount));
}

                        

                        

                            

                                
                                Secure Remediation (Pull-Payment Pattern)
                            

                            
// Let users withdraw individually on demand
function withdraw() external {
    uint amt = balances[msg.sender];
    balances[msg.sender] = 0;
    payable(msg.sender).transfer(amt);
}

 Mathematical Formulation & Methodology

                

                    

                        
1. Random Forest Gini Impurity

                        
Measures split impurity for each decision tree node across vulnerability classes $C$:

                        
$$I_G(p) = 1 - \sum_{i=1}^{C} p_i^2$$

                        
Where $p_i$ is the fraction of contracts belonging to class $i$ at that node.

                    


                    

                        
2. Ensemble Majority Voting

                        
Aggregates predictions from $T = 200$ independent decision trees:

                        
$$\hat{y} = \operatorname*{arg\,max}_c \frac{1}{T} \sum_{t=1}^{T} I(h_t(\mathbf{x}) = c)$$

                        
Provides soft probability distributions and confidence scores.
